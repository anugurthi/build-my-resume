# Sources

The guidance in this skill draws on the following public sources. Conventions change; check the originals for the latest wording.

## Resume writing standards
- **Harvard FAS Career Services — Create a Strong Resume**: resume language principles (specific, active, fact-based), action-verb lists, common mistakes, student section order.
  https://careerservices.fas.harvard.edu/resources/create-a-strong-resume/
- **r/EngineeringResumes Wiki**: single-column format, one page per decade, standard headings, date formatting (en dashes, "Present", months not seasons), plain URLs, bullet rules (no end periods, digits, 1–2 lines), recommended and superfluous verbs.
  https://www.reddit.com/r/EngineeringResumes/wiki/index/
- **Google XYZ formula** ("Accomplished X as measured by Y, by doing Z"), as described publicly by Laszlo Bock (former SVP People Operations, Google) and Google recruiters.

## Hiring process and ATS
- **Gergely Orosz — The Tech Resume Inside Out**: the hiring pipeline, 5–20 second resume scans, how ATSs actually work (databases + knockout questions, not auto-rejection), the origin of the "75% rejected by ATS" claim, PDFs being fine.
  https://thetechresume.com/samples/the-hiring-pipeline · https://thetechresume.com/samples/ats-myths-busted
- **Amazon Leadership Principles** (public list on amazon.jobs).

## Regional conventions
Compiled from public career-service guidance and common hiring practice in each market (e.g., UK/Irish university careers services, Make it in Germany, Europass). Treat as defaults; employers' own instructions win.

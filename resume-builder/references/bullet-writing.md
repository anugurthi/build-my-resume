# Writing Bullets That Get Interviews

## The formulas

**Google XYZ** (popularised by Laszlo Bock, former Google SVP People Ops):
> Accomplished **[X]** as measured by **[Y]**, by doing **[Z]**.

**CAR / STAR-compressed**: Challenge → Action → Result. On a resume the challenge is usually implied; lead with the action verb and end with the result.

**r/EngineeringResumes style**: *Action verb + what you did (with the specific tech) + measurable impact.* Front-load the strongest part. Keep each bullet to 1–2 lines.

Examples:
- Weak: "Responsible for the payment service."
- Strong: "Cut p99 checkout latency 42% (850ms → 490ms) by redesigning the payment service's retry and connection-pooling logic in Go."
- Weak: "Worked on CI/CD."
- Strong: "Reduced deployment time from 45 to 8 minutes for 30+ microservices by migrating Jenkins pipelines to GitHub Actions with parallelised test stages."
- Weak: "Helped team with mentoring."
- Strong: "Mentored 4 engineers through promotion to SDE II by running weekly design reviews and pairing on on-call incidents."

## Add domain context — the most underrated upgrade
Generic: "Developed web applications using React and Node.js"
With domain: "Developed credit-card issuance and payment-link features for a fintech platform using React and NestJS, serving 50K+ active cardholders"
For every role, find out: the industry (fintech, telecom, health, legal, logistics), the kind of data (payments, PII, medical, legal), who the users were (B2B, B2C, internal, government) and what the business cared about. One domain phrase per role often does more than a second metric. Avoid internal project codenames that only insiders understand.

## Rules (Harvard Career Services + engineering recruiters agree)
- Start every bullet with a strong past-tense action verb (present tense for ongoing work in the current role). No "Responsible for", "Worked on", "Helped", "Assisted with" unless nothing better is true.
- No personal pronouns (I, me, my, we). No articles where they add nothing.
- Be specific: name technologies, scale, and stakeholders.
- Quantify: %, $/€/£, time, users, requests/sec, team size, number of services, error rate, SLA, revenue, cost. Most strong bullets have at least one number; aim for the majority of bullets to have one.
- Show outcome, not duty. The test: "So what?" If the bullet still invites "so what?", add the result.
- One idea per bullet. Split compound bullets.
- No buzzwords without evidence ("synergy", "results-driven", "go-getter", "passionate", "hard-working", "team player", "detail-oriented").
- No period at the end of bullets (r/EngineeringResumes convention: bullets are fragments, not sentences). If the person's existing resume consistently uses periods, consistency matters more than the rule — just don't mix.
- Use digits, not words: "8 engineers", not "eight engineers".
- Avoid ampersands, slashes and apostrophes where a word reads better ("and", not "&"); no bold inside bullets; no sub-bullets.
- 1–2 lines per bullet; don't let 1–4 words spill onto a second line — trim instead.
- Name the tech used in the role inside the bullets as well as in Skills, so each skill has evidence.
- 3–6 bullets for the most recent/relevant role; 2–4 for older roles; 1–2 (or none) for roles 10+ years ago.

## Finding the numbers
Ask the person: How many users/customers? Traffic? Data volume? Before vs after (time, cost, errors, latency, conversion)? Team size you led/influenced? Budget? Revenue affected? How often did it run? Ranking (top x% of reviews, awards)?
If they truly don't know, estimate together and mark it ("~", "[confirm]"). Scale words ("company-wide", "all 12 regional teams") help when no number exists.

## Action verbs
Plain, specific verbs read as more credible to engineers and recruiters than grand ones.

- **Built/created**: Architected, Built, Created, Designed, Developed, Implemented, Integrated, Launched, Prototyped, Shipped, Deployed, Configured
- **Improved**: Accelerated, Automated, Cut, Decreased, Improved, Increased, Optimized/Optimised, Reduced, Refactored, Scaled, Simplified, Standardized, Streamlined
- **Led**: Coordinated, Defined, Directed, Established, Led, Managed, Mentored, Prioritized, Supervised
- **Analysed**: Analyzed, Assessed, Audited, Benchmarked, Diagnosed, Evaluated, Investigated, Profiled, Resolved, Troubleshot, Validated
- **Influenced**: Documented, Negotiated, Partnered, Presented, Proposed
- **Business results**: Delivered, Generated, Grew, Saved, Secured, Won
- **Operated**: Maintained, Migrated, Monitored, Operated, Supported
Vary verbs; don't start three bullets in a row with the same one.

**Avoid — superfluous or awkward** (r/EngineeringResumes wiki; Harvard lists some of these, but the engineering community reads them as fluff, and they're common tells of AI-written resumes): amplified, conceptualized, crafted, elevated, employed, engaged, engineered, enhanced, ensured, fostered, headed, honed, innovated, leveraged, mastered, orchestrated, perfected, pioneered, revolutionized, spearheaded, synergized, transformed, utilized

**Avoid — weak**: responsible for → name the action; helped / assisted → say what you did (contributed to, co-developed); worked on / was involved in → developed, built, implemented; participated in → contributed to, co-led; handled → managed, resolved
Also cut filler words: successfully, various, multiple (give the number), etc., excellent, innovative, strategically.
## Seniority signals by level
- **Entry/new grad**: shipped features, learned fast, projects with real users, internships, hackathons, measurable outcomes even if small.
- **Mid**: owned components end-to-end, measurable improvements, on-call/production ownership, cross-team work.
- **Senior**: designed systems, led projects of several engineers, set technical direction for a team, mentored, improved reliability/cost at scale.
- **Staff/Principal/Lead**: multi-team or org-wide impact, technical strategy, influenced roadmaps, raised the bar (standards, platforms, hiring), business outcomes in $ or strategic terms.
- **Manager**: team size, hiring, retention, delivery predictability, org outcomes, people growth (promotions).
Write at the level of the target job, using true examples.

## Project bullets
Name, tech stack, link (GitHub/demo) if public, then 1–3 bullets: what it does, what's technically interesting, traction (users, stars, downloads, awards).
